# Spec Delta

## Purpose

让 WitBoot 的开发者能在新工作区准备独立的本地资源，复现前后端运行环境并验证服务状态。明确开发、测试与生产之间的连接边界，便于后续需求在同一套可重复的环境中验收。

## ADDED Requirements

### Requirement: ENV-001 隔离运行环境

后端 SHALL 提供独立的开发和测试配置。生产配置仅在显式选择时启用。开发和测试的数据库及缓存连接 SHALL 通过对应环境的本地配置提供。

#### Scenario: 默认启动使用开发配置

- **WHEN** 开发者提供本地开发配置并启动后端，未显式指定生产 profile
- **THEN** 后端以开发配置运行，连接指定的开发数据库和缓存

#### Scenario: 缺少环境连接配置

- **WHEN** 开发者启动开发或测试环境，但缺少该环境所需的连接配置
- **THEN** 启动失败并指出缺失的配置项，错误输出不包含凭据

#### Scenario: 测试使用专用资源

- **GIVEN** 开发和测试使用独立的数据库及缓存资源
- **WHEN** 开发者按项目文档运行后端集成验证
- **THEN** 测试读写仅发生在测试资源中，开发数据与缓存保持原状

### Requirement: ENV-002 可重复启动和验证

项目 SHALL 提供从新工作区准备依赖、启动前后端、检查服务状态和停止服务的操作指引，并说明每项检查的预期结果。

#### Scenario: 从新工作区完成启动验证

- **GIVEN** 开发者具有文档列出的工具和专用本地资源
- **WHEN** 开发者按照文档配置并启动前后端
- **THEN** 后端健康检查返回就绪，前端可打开登录页并连接到本地后端

#### Scenario: 停止并再次启动

- **GIVEN** 本地前后端已经通过启动验证
- **WHEN** 开发者按文档停止并重新启动前后端
- **THEN** 同样的健康检查和页面访问可再次通过，已有开发数据保持原状
