# WitBoot 功能需求目录

WitBoot 面向个人和小团队，先验收可复用的 Java 后台母版，再提炼业务样板和项目生成能力。下面的中文文件记录各功能的需求编号、现有实现、设计草案、验收条件和变更链接。未单独记录状态的正式需求处于待梳理，候选项在立项前确认场景和优先级。

代码现状来自静态盘点。已有接口、页面或配置均进入复验范围，验收结果以运行证据为准。

## 修改功能需求

1. 打开对应的中文功能文件，用需求编号找到要改的行为，登记修改原因、期望结果和待确认的问题。
2. 正在审阅或实施的同一项变更，用 `$openspec-update-change` 更新其范围、增量规范、设计和任务。已验收的行为需要调整时，用 `$openspec-propose` 建立新变更并关联原需求编号。
3. 实施和验收后归档，将通过验收的行为同步到 `openspec/specs/`，在功能文件中回填主规范与归档链接。

中文名称用于功能文件、需求描述和验收场景。OpenSpec 能力与变更目录沿用英文短横线命名，例如 `user-management`。已存在的 OpenSpec 结构标题沿用当前项目配置。详见 [需求管理流程](需求管理.md)。

## 建议交付顺序

1. 验收本地开发与测试环境，再按独立变更落实数据库迁移、管理员初始化。
2. 按 USR-001 复验现有用户列表并归档已验证的业务规则。随后用 USR-002 练习修改分页参数行为。
3. 完成账号、部门、菜单、角色、权限和字典，根据关联关系分批验收。
4. 补齐审计、监控和持续交付。通过真实业务样板验证复用与 AI 工作流。
5. 从已验收的母版提炼项目生成能力，用第二个独立项目验收。
